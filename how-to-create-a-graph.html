How to Create a Graph

Turn any Sentinel or Defender table into an interactive graph in three steps: prepare your CSV data, write a small JSON config, and click Visualize.

Overview

The app works as a transformation pipeline. You bring tabular data (CSV rows), declare which columns are nodes and which columns describe edges between them, and the engine renders the graph.

CSV data
JSON config
Graph

No back-end, no install — everything runs in the browser.

1 Prepare your CSV data

The CSV must have a header row followed by at least one data row. Each row represents a relationship in your environment (e.g. a sign-in event, a network connection, an alert linked to an entity).

Minimal example — Login events

timestamp,user,machine,result
2025-07-01 08:10,alice@contoso.com,PC-ALICE-01,Success
2025-07-01 09:03,bob@contoso.com,SRV-FILE-01,Failure
2025-07-01 11:02,charlie@contoso.com,SRV-DC-01,Failure
2025-07-01 11:03,charlie@contoso.com,SRV-DC-01,Success

Where to get CSV data

SourceHow
Microsoft Sentinel Run a KQL query in Log Analytics → Export → CSV
Microsoft Defender XDR Advanced Hunting → run query → Export
PowerShell script Export the query results as CSV from Defender / Sentinel, rename the file to the exact graph name (e.g. Identity Logon Map.csv), place it in the data/ folder, then run .\Update-SentinelGraphs.ps1 — it will inject the CSV content into sentinel-graphs.json automatically.
Manual / test data Paste any CSV directly in the Editor panel

Values must not contain unquoted commas. If a value contains a comma or double-quote, wrap the whole value in double-quotes and escape inner quotes as "".

2 Write the JSON config

The config tells the engine which CSV columns become nodes and which columns describe edges between those nodes.

Full example

{
  "title": "Login Activity",
  "nodes": [
    {
      "id_column":    "user",     // column whose values become node IDs
      "type":          "user",     // icon shown inside the node circle
      "properties":   ["src_ip", "location"]  // extra info in the tooltip
    },
    {
      "id_column":    "machine",
      "type":          "machine"
    }
  ],
  "edges": [
    {
      "from_column":  "user",       // edge starts here
      "to_column":    "machine",    // edge ends here
      "label_column": "result",     // text displayed on the edge
      "color_map": {
        "Success": "#10b981",    // green
        "Failure": "#ef4444"     // red
      },
      "properties": ["timestamp", "src_ip"]
    }
  ]
}

Node properties

PropertyRequiredDescription
id_column RequiredCSV column whose values become the unique node identifier and label
type OptionalNode icon — one of the supported types. Defaults to default (gear icon)
type_column OptionalUse a CSV column to set the type per row instead of a fixed value
label_columnOptionalCSV column to use as the visible label (defaults to id_column)
properties OptionalArray of column names shown in the hover tooltip

Edge properties

PropertyRequiredDescription
from_column RequiredCSV column for the source node
to_column RequiredCSV column for the target node
label_columnOptionalCSV column whose value is printed on the edge arrow
label OptionalStatic label string for all edges in this definition
color OptionalDefault edge color as a hex string (e.g. "#6b7280")
color_map OptionalObject mapping label values to colors — overrides color per row
properties OptionalArray of column names shown in the hover tooltip on the edge

A single config can declare multiple node types and multiple edge types. The engine processes every combination per CSV row, so one table can produce a rich multi-entity graph in one shot.

3 Visualize

Open the Editor by clicking the Edit button in the toolbar. The editor has two tabs:

TabContent
Config (JSON)Paste or type your JSON config here
Data (CSV) Paste or type your CSV data here

Once both tabs are filled, click Apply & Visualize to render the graph. Errors (missing columns, malformed JSON, etc.) are displayed inline so you can fix them without leaving the editor.

After visualizing, click the Visual tab in the editor to tweak node types and edge colors using a point-and-click interface instead of editing JSON manually.

Using the Build Graph Wizard

If you prefer a guided experience, click Build Graph in the toolbar. The wizard walks you through the same three steps above with interactive dropdowns and pickers.

Wizard steps
1 — Paste CSV  ·  2 — Pick node columns & types  ·  3 — Pick edge columns & colors  ·  4 — Preview & render

The wizard generates the JSON config automatically and hands it to the engine. You can inspect the generated JSON at any time by switching to the Editor after the graph is rendered.

Advanced options

Dynamic node type from a column

If your CSV has an entity_type column (e.g. user, ip, machine), use type_column instead of a fixed type:

{
  "id_column":   "entity",
  "type_column": "entity_type"   // value per row drives the icon
}

Multiple node types in one graph

"nodes": [
  { "id_column": "alert_id", "type": "alert" },
  { "id_column": "user",     "type": "user"  },
  { "id_column": "machine",  "type": "machine" }
],
"edges": [
  { "from_column": "alert_id", "to_column": "user",    "label_column": "severity" },
  { "from_column": "alert_id", "to_column": "machine", "label_column": "severity" }
]

GQL filter bar

Use the GQL bar at the bottom of the graph to filter nodes and edges without re-loading data. See the full GQL reference below for the complete syntax.

Collapse / expand groups

Double-click any node to collapse all its neighbours of the same type into a single group node. Double-click the group to expand it again.

GQL filter bar

The GQL bar sits at the bottom of the graph canvas. Type a query and press Enter (or click Run) to filter the visible graph. Press Esc or click ✕ to restore the full graph.

GQL filters act on the already-rendered graph — no CSV re-parsing, no page reload. Nodes and edges that do not match are hidden; matching ones remain visible.

Clause structure

Every GQL query follows the same skeleton:

MATCH <pattern> [WHERE <condition> [AND <condition> ...]] RETURN <aliases>

Pattern syntax

PatternMeaning
(n)Any node, bound to alias n
(n:user)Any node whose type is user
(a)-[r]->(b)Any directed edge from a to b, relationship bound to r
(a:user)-[r]->(b:machine)Edge from a user node to a machine node

WHERE conditions

Filter on node or edge properties using alias.property notation. Multiple conditions are joined with AND.

OperatorExampleMatches when…
= n.id = 'alice' value equals exactly (case-insensitive)
CONTAINS n.id CONTAINS 'ali' value contains the substring (case-insensitive)
STARTS WITHn.id STARTS WITH 'srv' value starts with the prefix (case-insensitive)

Accessible properties

Alias targetPropertyValue
Node alias (e.g. n, a, b).id Node identifier (the value from id_column)
.labelDisplayed label
.type Node type string (e.g. user, machine)
Edge alias (e.g. r) .labelEdge label (the value from label_column)

RETURN clause

List the aliases you want to keep visible, separated by commas. For node-only queries use the single node alias; for edge queries include both node aliases and the relationship alias.

// Node query — return the node alias
MATCH (n:machine) RETURN n

// Edge query — return both nodes and the edge
MATCH (a)-[r]->(b) RETURN a,r,b

Examples

── Node queries ──────────────────────────────────────────────

// All nodes
MATCH (n) RETURN n

// Only user nodes
MATCH (n:user) RETURN n

// Node whose ID equals a value exactly
MATCH (n) WHERE n.id = 'alice@contoso.com' RETURN n

// Nodes whose ID contains a substring
MATCH (n) WHERE n.id CONTAINS 'srv' RETURN n

// Machines whose label starts with 'SRV-DC'
MATCH (n:machine) WHERE n.id STARTS WITH 'SRV-DC' RETURN n

// Filter by type via WHERE (equivalent to :user in the pattern)
MATCH (n) WHERE n.type = 'ip' RETURN n


── Edge queries ──────────────────────────────────────────────

// All edges
MATCH (a)-[r]->(b) RETURN a,r,b

// Edges from user to machine
MATCH (a:user)-[r]->(b:machine) RETURN a,r,b

// Only successful sign-ins
MATCH (a)-[r]->(b) WHERE r.label = 'LogonSuccess' RETURN a,r,b

// Failed logins originating from a specific user
MATCH (a)-[r]->(b) WHERE a.id CONTAINS 'charlie' AND r.label = 'LogonFailed' RETURN a,r,b

// Lateral movement to a specific server
MATCH (a:machine)-[r]->(b:machine) WHERE b.id CONTAINS 'SRV-DC' RETURN a,r,b

String values in GQL conditions must be wrapped in single quotes ('value'). Double quotes are not supported.

Connecting to live Sentinel / Defender data

You can embed a KQL query inside the config's "query" field. The query is stored alongside the graph and can be viewed in-app via the KQL button in the toolbar.

To populate the csv field with real data, follow these steps:

  1. Run each KQL query manually in Microsoft Defender XDR → Advanced Hunting or in Microsoft Sentinel → Logs.
  2. Export the results as CSV using the Export button.
  3. Rename the downloaded file to the exact graph name (e.g. Identity Logon Map.csv).
  4. Place the file in the data/ folder next to this project.
  5. Run the PowerShell script — no parameters needed:
# Reads all CSVs from data/ and injects them into sentinel-graphs.json
.\Update-SentinelGraphs.ps1

The script matches each CSV filename (without extension) to the corresponding graph name in sentinel-graphs.json, overwrites the csv field with the file content, and saves the JSON. Reload index.html to see the updated data.

The "query" field in the config is purely informational — it is shown in the KQL button tooltip but is never executed automatically. Data only updates when you manually export a CSV and run the script.
